# Development Decisions

This document separates active decisions from superseded historical choices and pending production decisions.

## Active Decisions

- `client/` is the official and only frontend.
- `server/` is the official Express/Node backend.
- The legacy root `src/`, root `public/`, and root `logo.svg` have been removed.
- The project remains a React + Express + MySQL modular monolith.
- Database changes are managed through numbered SQL migrations and the `schema_migrations` table.
- The standard database name is `cyberly`.
- Login uses email and password.
- Public registration creates `user` accounts only.
- Public admin self-registration is prohibited.
- Admin access is enforced server-side from the authenticated session and database role.
- First production roles are `user` and `admin`.
- Passwords are stored as bcrypt hashes in `users.password_hash`.
- Sessions are server-side through `express-session` and the MySQL-backed session store.
- Session payloads store only `userId` and `role`.
- Registration and login regenerate sessions to reduce session-fixation risk.
- Session cookies are HTTP-only and use production secure behavior when configured for production/cross-origin hosting.
- Learner-profile fields are persisted separately from authentication identity in `learner_profiles`.
- `GET /api/auth/me` restores a safe user object and normalized learner profile.
- Age is collected during registration and validated as a whole number from 1 to 120.
- Age groups are `child`, `teen`, `young_adult`, and `adult`.
- Age and education level are not treated as measured learning ability.
- Adaptive difficulty and recommendations should be based on measured assessment/scenario/progress signals, not age category.
- The Initial Cyber Wellness Assessment is fixed, versioned, migration-seeded content.
- Assessment scoring is deterministic and calculated only on the backend.
- Scenario content is fixed or Admin-managed approved content, not generated by AI at runtime.
- Scenario decisions are final after submission.
- Scenario completion updates progress idempotently through `scenario_progress_events`.
- CyberGuard provider calls are backend-only.
- Browser-side direct AI provider calls are prohibited.
- RAG uses reviewed/RAG-ready content and returns source metadata separately from action routes.
- Action cards and learner-controlled proposals must use trusted internal targets only.
- Controlled Agentic AI is backend-orchestrated and must not autonomously mutate scores or start/complete learning activities.

## Superseded Decisions

- The root React app was previously retained as legacy reference. It has now been removed.
- CyberGuard was previously a frontend-only chat shell. It is now connected to the backend AI gateway, persistence, RAG, sources, action cards, and controlled Agentic logic.
- Resource learning content was previously treated as frontend/static content. Current Resource content is represented through backend Resource APIs and MySQL Resource tables.
- Admin was previously only planned. A protected Admin Console and Admin APIs now exist.
- Learner onboarding was previously not persisted. Learner profile data is now stored in `learner_profiles`.

## Pending Production Decisions

- Production provider preference between OpenAI, Gemini, and ILMU remains a product/operations decision. Current configuration supports the provider gateway and purpose assignments; `server/.env.example` defaults to OpenAI and disables Gemini runtime by default.
- Broader public rate limiting beyond the current authentication-focused in-memory limiter needs production design.
- Durable storage or signed-token handling for learner-controlled action proposals needs a production decision before multi-instance deployment.
- Migration rollback and database backup/restore workflow remain pending.
- Formal AI safety, multilingual, accessibility, performance, and security evaluation processes remain pending.
- Fine-grained Admin role and audit policy remains pending.
